# Media Intelligence Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a shared media-intelligence layer to Nico Workbench with viral analysis, a drama library, a daily industry-news radar, and Mentor fusion across historical and new evidence.

**Architecture:** Keep existing publish records as the source of truth for new posts, then add focused media-intelligence modules through an injected `media-intelligence.js`/CSS layer to avoid rewriting the packed Nico shell. Store structured viral/drama data in the existing Nico local state, store uploaded MP4 blobs in IndexedDB, and load daily news from a static `news.json` generated by a GitHub Actions script. Mentor Case generation will merge publish, viral, drama, risk, and news evidence while preserving provenance.

**Tech Stack:** Vanilla JavaScript/CSS in Nico static shell, localStorage-compatible Nico state, IndexedDB, Node.js 22 news script, GitHub Actions, OpenAI API, Vitest for repository-level contract tests.

**Spec:** `docs/superpowers/specs/2026-08-26-media-intelligence-layer-design.md`

## Global Constraints

- TikTok only; do not introduce a cross-platform channel abstraction.
- Existing publish records remain the source of truth for new content.
- Viral auto-entry rule: views >= 100000 OR views >= 3x the account recent median.
- Account recent median uses the latest 10 eligible normal posts; fewer than 5 eligible posts disables the 3x rule.
- Exclude hidden/violating/deleted/no-view posts from account-baseline calculations.
- Viral sync is idempotent: one publish record maps to at most one auto-synced viral item.
- Metric updates append dated snapshots; they do not overwrite historical snapshots.
- Uploaded MP4 blobs go to IndexedDB, never localStorage.
- News panel stores only medium/high-impact items; low-impact items are discarded.
- OpenAI API key lives only in GitHub Actions secrets and is never shipped to GitHub Pages.
- News classification uses title/summary first; deeper analysis only runs on medium/high-impact items.
- Mentor recommendations must expose evidence provenance and avoid causal claims from hashtags/news correlations.
- Do not regress existing Media pages, Media data, or the BD workspace.
