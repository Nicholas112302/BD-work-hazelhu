# Nico Workbench 影视运营知识层设计说明

## 目标
在现有「🎬 影视运营」工作区上新增一套共享影视运营知识层，让以下模块读取同一批可追溯数据，并彼此反哺：

- 🔥 爆款分析
- 📰 影视行业新闻雷达
- 🎞️ 片单库
- 账号作战地图
- 发布录入
- 违规风险中心
- Mentor

核心闭环：新闻趋势 → 片单优先级 → TikTok 账号推荐 → 发布 → 数据回流 → 爆款/风险判断 → Mentor 更新策略 → 再反哺片单推荐。

本阶段只针对 TikTok，不新增 Reels / YouTube Shorts 等平台层。

---

## 一、共享影视运营知识层

### 1. 数据原则

现有发布记录仍是「新内容」的事实来源，不复制一套互相冲突的发布数据库。

新增三类长期实体：

1. `viralItems`：爆款/潜力爆款素材记录
2. `dramaLibrary`：片单库剧集记录
3. `industryNews`：中高影响行业新闻

它们通过稳定 ID 与现有发布记录、账号、剧名关联。

### 2. 证据优先
所有 Mentor 判断必须能指出依据来自：

- 历史爆款
- 近期发布表现
- 账号近期基准
- 违规/隐藏记录
- 片单信息
- 中高影响行业新闻

不能只显示一个无法解释的 AI 分数。

### 3. 本地存储

影视结构化数据继续保存在现有 Workbench 本地数据体系中，保持兼容。

视频文件不得放入 localStorage。历史爆款/补录素材的 MP4 使用 IndexedDB 存放，只在本机浏览器保存；记录本身保存 `videoAssetId` 作为引用。

需要在 UI 明确提示：清除浏览器站点数据可能删除本地视频文件，因此视频文件应支持重新选择/替换。

## 二、🔥 爆款分析面板

### 1. 数据来源

支持两种来源：

- `historical_manual`：历史爆款手动补录
- `publish_sync`：来自现有发布录入的自动同步

历史补录支持：

- 视频链接
- 本地 MP4
- 两者同时存在

### 2. 每条素材字段

至少包含：

- 来源类型
- 关联发布记录 ID（如有）
- TikTok 账号
- 剧名
- 发布时间（如已知）
- Caption 原文
- Caption 中文翻译（如有）
- 内容运营方向
- 普通 Hashtag
- 片名 Hashtag
- 视频链接
- 本地视频引用
- 违规状态 / 隐藏状态
- 用户备注
- 首次进入爆款库时间
- 当前爆款状态标签
- 数据快照时间线

### 3. 自动进入规则

满足任一条件即可成为 `🔥 新爆款候选`：

1. 播放量 ≥ 100,000
2. 播放量 ≥ 该账号近期播放量中位数 × 3

账号近期基准：

- 使用该账号最近 10 条有效正常发布记录
- 排除系统隐藏/违规、已删除、无播放量数据的记录
- 有效记录少于 5 条时，不启用 ×3 相对判断，只使用 100K 固定门槛

### 4. 自动检查时机

两条路径都支持：

- 用户在发布记录中补填/修改播放量时即时判断
- 爆款分析面板提供「重新扫描全部记录」按钮，批量检查漏网和后期爆发记录

自动同步应幂等，同一发布记录只能对应一条 `publish_sync` 爆款记录，不重复创建。

### 5. 数据快照与二爆

更新播放/点赞/涨粉时不覆盖旧值，而是新增一条带日期的数据快照。

每次更新默认使用当天日期，允许用户修改。

系统可根据增长轨迹增加标签：

- 🔥 首爆
- 🌱 慢热
- 🚀 二爆
- 📈 长尾增长

标签是辅助描述，必须保留原始快照时间线作为证据。

### 6. 爆款结构分析

Mentor 分析维度包括但不限于：

- Hook 类型
- 前几秒冲突方式
- 核心冲突类型
- 爽点 / 反转位置
- 身份曝光、霸凌反击、情感冲突等内容方向
- Caption 写法
- Hashtag 组合
- 剧集
- 账号
- 违规风险
- 同类结构近期是否仍有效

历史单条爆款只算强信号，不直接证明长期适配。

## 三、🎞️ 片单库

### 1. 目的

片单库作为所有可用/待用剧集的长期库存与策略资料库，而不是简单片名列表。

### 2. 每部剧字段

至少包含：

- 剧名
- 主演
- 题材
- 现代 / 古装
- 是否爱奇艺
- 剧情标签
- 重点冲突类型
- 库存状态
- 是否已剪辑
- 是否正在投放
- 历史发布账号
- 历史最高播放
- 违规情况
- 备注

### 3. TikTok 账号适配推荐

每部剧展示各 TikTok 账号的建议状态与解释：

- 🟢 推荐
- 🟡 可测试
- 🔴 暂不建议
- ⚠️ 风险偏高

推荐综合：

- 该账号近期中位表现
- 同剧历史表现
- 同类题材/内容方向表现
- 爆款库证据
- 违规风险
- 新闻相关性
- 数据新鲜度

可以提供 0–100 的内部辅助分，但 UI 必须同时展示可读原因，分数不能替代证据。

### 4. 动态变化

推荐不是永久状态。发布数据、违规数据、爆款数据或中高影响新闻变化后，推荐可重新计算。

发布录入选剧时应能读取片单库，并展示当前推荐 TikTok 账号/风险提示。

## 四、📰 影视行业新闻雷达

### 1. 目的

独立面板，每天自动收集与印尼影视/娱乐行业有关、且可能影响影视内容运营判断的新闻。

不做普通明星八卦聚合器。

### 2. 收录范围

优先考虑：

- 印尼演员/艺人的重大争议或明显舆情
- 热门演员重要新剧、合作、节目或项目官宣
- 流媒体/影视平台政策变化
- TikTok 等短视频平台会影响影视内容分发或审核的变化
- 内容审查、版权、监管变化
- 影视公司、平台的重大合作/版权变化
- 已形成明显大众讨论、可能改变演员/题材热度的娱乐事件

普通恋爱八卦、低讨论度通稿、小范围粉圈动态默认过滤。

### 3. 影响等级

仅中高影响进入新闻面板：

- 🔴 高影响：可能直接影响选剧、演员选择、平台策略、审核/版权或重大风险
- 🟠 中影响：值得跟进，可能影响近期内容判断或借势机会
- ⚪ 低影响：不写入工作台

当天没有中高影响新闻时，显示：

> 今日暂无需要跟进的影视行业动态。

### 4. 每条新闻保存内容

- 标题
- 日期
- 新闻来源
- 原文 URL
- 涉及演员
- 涉及剧集/平台
- 影响等级
- 简短事实摘要
- 为什么值得关注
- 对 TikTok 影视运营的可能影响
- 与片单库的关联项
- Mentor 建议动作
- 抓取时间
- 去重键

### 5. 自动更新架构

GitHub Actions 每天定时执行一次新闻任务：

1. 从配置的 RSS / 新闻搜索源抓取候选
2. URL + 标题归一化去重
3. 规则初筛：语言、地区、主题、重复、明显低价值内容
4. 使用轻量 OpenAI API 模型批量判定低/中/高影响
5. 只对中高影响新闻做第二阶段摘要与运营关联分析
6. 写入版本化 `news.json`
7. GitHub Pages 的新闻面板读取该静态 JSON

新闻任务独立于 ChatGPT Plus 额度，使用 OpenAI API key；API 费用与 Plus 分开。

### 6. 成本保护

新闻雷达必须有每日预算保护：

- 限制每日候选新闻数量
- 标题/摘要先筛，不先发送全文
- 只有中高影响进入第二阶段
- 对已处理 URL/标题不重复消耗
- 超过预算阈值时停止深度分析并在日志注明

API Key 只保存在 GitHub Actions Secret（例如 `OPENAI_API_KEY`），绝不能写进前端、仓库源码或 Pages 静态文件。

### 7. 新闻可靠性

AI 不应把新闻推断写成事实。事实摘要需要保留来源 URL 和来源名。

同一事件多个来源时尽量合并为一个事件；重大高影响新闻优先要求至少两个独立来源，若只有单一来源则标记「单一来源，待观察」。

## 五、Mentor 融合分析

### 1. Mentor 读取范围

Mentor Case 构建时可读取：

- 片单库
- TikTok 账号作战地图
- 最近发布表现
- 爆款历史及数据快照
- 违规风险
- 中高影响行业新闻

### 2. 输出要求

Mentor 的推荐必须区分：

- 历史证据
- 近期证据
- 新闻/外部趋势证据
- 风险证据

示例结论可为：

> 历史上有效，但近期衰退。旧样本 8 条中 6 条高于基准；最近 5 条只有 1 条高于近期中位数。建议保留身份曝光结构，但缩短羞辱铺垫，先测试 3 条再决定是否继续。

或：

> 今日优先测试《X》→ Account B：Account B 最近同类冲突内容高于自身基准，历史爆款库存在同结构样本，主演今天出现中影响新闻，且近期违规风险低。

### 3. 防止错误归因

- 新闻相关性只能作为辅助信号，不能直接声称新闻“导致”播放提升
- Hashtag 相关性不能直接声称因果
- 单条爆款不能永久锁定剧集 × 账号关系
- 趋势结论应优先使用近期中位数和多条样本

## 六、导航与页面

影视运营侧栏新增：

- 🔥 爆款分析
- 🎞️ 片单库
- 📰 新闻雷达

现有「推荐片单」可以逐步由片单库的账号适配视图替代，但第一阶段不删除旧页面，避免破坏既有流程；完成验证后再决定是否合并。

---

## 七、数据安全与兼容

- 不删除或改写现有真实发布记录
- 新字段使用向后兼容默认值
- 自动同步必须幂等
- 视频二进制与结构化记录分离
- 新闻 API key 只存在 GitHub Secret
- 新闻 JSON 不包含任何 secret
- 清空演示数据只影响演示记录，不删除真实爆款、片单或新闻
- 清空全部本地影视数据时，需要单独提示本地 IndexedDB 视频也会被清理（若实现联动清理）

---

## 八、成功标准

1. 可以手动补录旧爆款，并使用链接或本地 MP4。
2. 新发布达到 100K 或账号近期中位数 ×3 时自动进入爆款候选。
3. 后补播放量、二爆、慢热内容可以通过数据快照更新，并保留历史值。
4. 可以一键重新扫描全部发布记录，不产生重复爆款条目。
5. 片单库可以对每部剧给出 TikTok 账号适配建议及证据。
6. 新闻雷达每天自动运行，只展示中高影响新闻；无重要新闻时不硬填内容。
7. 新闻自动任务不暴露 OpenAI API key，并有每日成本上限。
8. Mentor 能同时引用历史爆款、近期发布、片单、账号表现、违规和新闻进行融合分析。
9. 任何推荐都能解释证据，不使用不可解释的黑箱结论。
10. 现有影视运营页面、数据和 BD 工作区不退化。
