# Nico Workbench 双工作区设计说明

## 目标
把现有 Nico Workbench 扩展为一个工作台中的两套独立工作区：

- 🎬 影视运营
- 💼 BD 运营

两边共享 Nico Workbench 外壳与视觉语言，但页面、导航、数据和业务逻辑保持独立。

## 已确认交互
左侧顶部加入工作区切换器：

- 影视运营 ▾
- BD 运营 ▾

切换工作区时，左侧菜单、主内容区和工作区标题一起切换。

## 影视运营工作区
保留当前已上线功能，不改变已有数据：

- 首页 / 今日计划
- 发布录入
- 账号作战地图
- 推荐片单
- Hashtag 分析
- 违规风险中心
- Mentor
- 公司报表搬运
- 数据与备份

## BD 运营工作区
复用仓库中现有 Creator / Outreach 工作台的成熟逻辑，避免重写。

主要入口：

- BD 首页 / 今日跟进
- KOL / 社群数据库
- 合作 Pipeline
- 待回复 / 待跟进
- Campaign / Product
- 消息话术 / AI 辅助
- 内容交付 / 合作状态
- BD 数据与导入导出

后续可继续扩展交易所 BD 专属字段：固定合作费、Referral、KYC/首充/交易量、Day1 Retention 等。

## 数据隔离

影视运营继续使用现有 Nico Workbench localStorage 数据。

BD 工作区沿用原 BD 工作台自己的 localStorage / 数据结构。两套数据不共用账号、剧集、达人、Campaign 等实体。

工作区选择状态可以单独使用 `nico_active_workspace` 保存，仅记录用户最后打开的是 media 还是 bd，不保存业务数据。

## 集成方式

第一阶段采用“同一 Nico Workbench 外壳 + 独立 BD 应用嵌入/挂载”的方式：

- 影视工作区继续使用现有单页应用。
- BD 工作区复用仓库现有 BD 应用，不复制业务逻辑到影视代码。
- 切换到 BD 时隐藏影视导航与内容，显示 BD 工作区入口与 BD 应用内容。
- 切回影视时恢复当前 Nico Workbench，不刷新或清空影视数据。

优点：数据天然隔离、改动风险低、最快可上线，并且以后可以逐页把 BD 视觉统一到 Nico Workbench。

## 演示与清理

影视运营「演示与清理」区域保留三个动作：

1. 载入演示数据
2. 清空演示数据 — 只删除演示记录，不删除用户真实记录
3. 清空全部本地数据 — 危险操作，删除影视工作区全部本地数据

BD 工作区的 Demo Mode / 清理逻辑继续按其原应用规则独立运行，不与影视工作区互相删除。

## 成功标准

- 能从 Nico Workbench 内明显切换「影视运营 / BD 运营」。
- 两边菜单不会混在一起。
- 切换不会删除或覆盖任何一边已有 localStorage 数据。
- 影视运营现有页面和逻辑不退化。
- BD 现有 Creator / Outreach 流程可继续正常使用。
- 「清空演示数据」只影响影视演示数据。
